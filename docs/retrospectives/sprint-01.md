Day 3 — Database schema. Six migrations authored in dependency order, all using UUID v4 primary keys via a project-local trait (HasUuidPrimaryKey) rather than calling Laravel's Str::uuid() ad-hoc in controllers. ADR-0001 records the UUID strategy and the conditions under which it should be reconsidered (>5M rows, query-plan bottleneck, or real-time analytics requirement). One scope extension noted: a fourth behavioral_events.event_type enum value (rapid_zone_transition) was added beyond the three documented in §3.3 of the AT2 report. This reflects implementation-level refinement of the Zone-Based Logic — the three documented event types remain canonical; the fourth is an internal distinction between sustained pacing and rapid zone-crossing. To be explained in the AT4 review chapter under "scope refinements during implementation". One denormalisation also noted: current weight, BMI, and BMR are stored on the pets table as well as in health_records, write-time updated by the application layer to avoid an expensive read-time subquery. Defensible and documented.

**Day 7 — HealthRecord resources and server-side biometrics.** Implemented FR-03 (real-time biometric profile generation). BMI and BMR are computed server-side by an isolated BiometricCalculator domain service — null-safe, dependency-free, unit-tested in isolation against hand-computed values. Client-supplied BMI/BMR is never trusted (proven by store_ignores_client_supplied_bmi_and_bmr). Honest limitation recorded in ADR-0005: the BMI formula is the human weight/height² index, which is not a clinically valid canine metric (the 9-point Body Condition Score is the veterinary standard); retained per project spec as a "morphological proxy" with the limitation acknowledged rather than concealed — this honesty strengthens the AT4 critical-evaluation narrative. Schema discipline maintained: Day 3's migration is immutable, so an additive migration added the new clinical vitals (height_cm, temperature_c, heart_rate_bpm) and existing columns were reused. HealthRecordPolicy extends the RBAC model — vets gain create + scoped-update rights they lacked for pet metadata, and clinical records are not deletable by their authors (audit integrity). Suite now ~78 tests.
